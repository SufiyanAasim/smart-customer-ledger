# v4.0.0 — Chronicle

## Overview

Chronicle is the documentation-focused release: no application or database code changed.
It produces the complete academic documentation package required for course submission and
viva defense — a project proposal, final report, ten diagrams, a twelve-file database
dictionary, nine hands-on labs, nine testing documents, six manuals, viva preparation, and
grading/submission checklists — all cross-checked against the actual codebase as it stood
at the end of v3.0.0 — Snapshot, not written speculatively ahead of the implementation.

Chronicle is **not** the final release — v5.0.0 (Replica) and v6.0.0 (Shard) follow it.

## Objectives

- Produce a proposal and final report that accurately describe what was actually built.
- Document the database schema, relationships, constraints, indexes, views, triggers, and
  scheduled mechanisms in enough detail to stand alone from the code.
- Provide hands-on labs that a grader or student can follow step-by-step against a real
  running instance.
- Provide a complete, honest testing document set, including a requirements traceability
  matrix and an evidence checklist that does not fabricate screenshots or command output.
- Provide manuals for installation, configuration, database setup, end users, and
  administrators, plus a troubleshooting guide.
- Provide viva Q&A and a demonstration script grounded in the real application.
- Provide grading and submission checklists.

## Known Limitations

- Diagrams are Mermaid source, not rendered image files — render them with any Mermaid-
  compatible viewer (GitHub renders `.md` Mermaid blocks natively) or `mmdc` for a static
  image if one is needed for a printed submission.
- The Evidence-Checklist's screenshots and command-output items are explicitly unchecked
  placeholders — they require manual capture against a real running instance and are not,
  and should not be treated as, already-collected evidence.
- No new automated tests — Chronicle is documentation-only.
