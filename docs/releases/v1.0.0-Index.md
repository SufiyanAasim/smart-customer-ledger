# v1.0.0 — Index

## Overview

Index is the foundational release of CustomerLedger: the database schema, the ASP.NET Core
MVC application architecture, authentication/authorization, and the first working CRUD
workflow across every business entity in the system. It establishes everything later
releases build on — Balance (v2.0.0) adds full transactional financial workflows on top of
the foundation laid here; it does not need to touch this release's schema again.

## Objectives

- Stand up a modular-monolith solution (Domain / Application / Infrastructure / Web) on
  .NET 8 LTS and MySQL 8.0 via EF Core + Pomelo.
- Model all 11 business entities with correct keys, constraints, indexes, and relationships.
- Implement ASP.NET Core Identity with three roles and enforced branch isolation.
- Deliver a working (if not yet fully transactional) CRUD workflow for every module listed
  in the project specification.
- Produce the six required SQL views, safe initial triggers, and explicit parameterized SQL
  CRUD scripts for every core table.
- Establish a real (not fabricated) automated test suite.

## Database Changes

- **Tables**: Branches, Customers, CustomerAccounts, Invoices, InvoiceItems, Payments,
  InstallmentPlans, InstallmentSchedules, CustomerInteractions, AuditLogs, BackupHistories,
  plus the 7 standard ASP.NET Core Identity tables (AspNetUsers extended with FullName,
  BranchId, EmployeeCode, IsActive, CreatedAtUtc, LastLoginAtUtc).
- **Constraints**: unique BranchCode/EmployeeCode/CustomerCode/InvoiceNumber/PaymentNumber,
  FK relationships with `RESTRICT` on financial data and `CASCADE` only for
  Invoice→InvoiceItems and InstallmentPlan→InstallmentSchedules, CHECK constraints on
  quantities/prices/amounts and cross-column date ordering.
- **Indexes**: every index listed in the project specification section 8, each backed by a
  documented query pattern — see `database/indexes/CreateIndexes.sql`.
- **Views**: `vw_CustomerAccountSummary`, `vw_InvoicePaymentStatus`,
  `vw_OverdueInstallments`, `vw_BranchRevenueSummary`, `vw_CustomerInteractionHistory`,
  `vw_DailyTransactionSummary`.
- **Triggers**: invoice item validation (BEFORE INSERT/UPDATE), payment-vs-cancelled-invoice
  rejection (BEFORE INSERT), financial audit logging (AFTER INSERT/UPDATE on Payments),
  physical-deletion prevention on Customers/Invoices/Payments (BEFORE DELETE).
- **Migration**: `20260730120701_InitialCreate` under
  `src/CustomerLedger.Infrastructure/Data/Migrations`.

## Security

- Parameterized SQL throughout — no string-concatenated queries anywhere.
- ASP.NET Core Identity handles all credential storage/verification.
- Branch isolation enforced server-side (`ICurrentUserContext.CanAccessBranch`), independent
  of anything hidden or shown in the UI.
- Anti-forgery tokens on every POST form; ViewModels prevent over-posting onto entities.
- No hardcoded credentials, branch ids, or user ids anywhere in the codebase.
- `appsettings.json` ships with an empty connection string; secrets are read from user
  secrets / environment variables only.

## Known Limitations

- No full ACID/rollback/concurrency demonstration lab yet — payment posting is
  transactional (`START TRANSACTION`/`COMMIT` in the service and in
  `database/crud/Payments_CRUD.sql`), but the dedicated forced-rollback and concurrent-
  payment demonstrations are Balance-release scope.
- Backup/restore execution, CSV/JSON export/import, and demonstration/large-volume seeders
  are Snapshot-release scope.
- No dedicated MVC Areas for Branch Manager/Staff — they share the root controllers with
  Administrator, differentiated by role/branch checks in the service layer, to avoid
  duplicating near-identical views across three areas.
- Full academic documentation (proposal, final report, ER/architecture diagrams, labs, viva
  prep, database dictionary) is Chronicle-release scope.
- No read replica or sharding — Replica and Shard releases respectively.
