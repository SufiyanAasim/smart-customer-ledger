# v3.0.0 — Snapshot

## Overview

Snapshot gives CustomerLedger real data-recovery and data-movement workflows: actual
backup/restore execution against MySQL (not a placeholder that always reports success),
validated CSV/JSON export, a preview-before-write CSV import, and seed scripts for both a
coherent demonstration dataset and a bounded large-volume dataset for index/performance
demonstrations.

## Objectives

- Execute real backups via `mysqldump` and record the actual outcome in `BackupHistory` —
  never mark a row Completed unless the process exited 0 and produced a non-empty file.
- Provide a symmetric restore path via the `mysql` client, gated behind an explicit typed
  confirmation, Administrator-only.
- Export Customers/Invoices/Payments/account statements to CSV, and Customers to JSON, with
  defense against CSV formula injection.
- Validate a customer CSV import before writing anything — preview, then a separate
  confirmed write, never a single "just import it" action.
- Ship demonstration and large-volume seed scripts distinct from the Index release's
  minimal `DevelopmentSeed.sql`.

## Added

- `IBackupService`/`MySqlBackupService`: shells out to `mysqldump` (password passed via the
  `MYSQL_PWD` environment variable, never a visible command-line argument), writes the
  dump to a configurable directory, and records `BackupHistory.Status` from the actual
  process exit code and resulting file size.
- `IRestoreService`/`MySqlRestoreService`: streams a previously completed backup file into
  the `mysql` client to restore it.
- `CsvUtilities` (Application layer, no DB dependency): RFC-4180-ish CSV parsing/writing
  with formula-injection neutralization (a field starting with `=`, `+`, `-`, or `@` gets a
  leading apostrophe) — shared by every export and the importer.
- `IExportService`/`ExportService`: CSV for Customers/Invoices/Payments, JSON for Customers,
  and a combined CSV account statement (invoices + payments) for one customer.
- `IImportService`/`ImportService`: validates a customer CSV (required columns, duplicate
  CustomerCode within the file and against the branch, row-level rejection reasons) via
  `PreviewCustomerImportAsync`, then `ImportCustomersAsync` re-validates and writes only
  the accepted rows in one transaction.
- Web UI: Admin → Backup History gains a "Run Backup Now" button and a typed-confirmation
  restore action; Customers/Invoices/Payments list pages gain CSV (and, for Customers,
  JSON) export links; Customers gains an Import screen (upload → preview → re-upload to
  confirm).
- `database/seed/DemonstrationSeed.sql`: a coherent two-branch, five-customer story
  covering a fully paid invoice, a partially paid one, an overdue unpaid one, and an active
  installment plan.
- `database/seed/LargeDatasetSeed.sql`: a stored-procedure loop generating a bounded,
  explicitly-reported number of synthetic customers/invoices (2,000 by default) in a
  dedicated `PERF-TEST` branch, for `EXPLAIN` demonstrations that need real volume.

## Security

- The backup/restore database password is passed to the child process via the `MYSQL_PWD`
  environment variable, never as a command-line argument (which would be visible to any
  other process able to read the OS process list).
- Restore is Administrator-only and requires typing the literal word `RESTORE` in the form,
  in addition to CSRF protection — a destructive, whole-database-overwriting action gets
  more friction than a normal delete.
- CSV export neutralizes formula injection (a cell that would otherwise execute as a
  formula when opened in Excel/Sheets gets a leading apostrophe).
- CSV import re-validates on the actual write call — a client cannot bypass validation by
  skipping the preview step and calling import directly, because `ImportCustomersAsync`
  runs the same `ValidateAsync` logic itself.
- Import is capped at 2 MB and requires the branch match the current user's branch (or an
  Administrator-specified branch).

## Known Limitations

- Backup/restore requires the `mysqldump`/`mysql` client binaries on the server's PATH (or
  configured via `BackupSettings:MysqldumpPath`/`MysqlClientPath`) — there is no pure-.NET
  fallback.
- Import supports Customers only; Invoice/Payment import is not implemented (those records
  should originate from the application's own transactional workflows, not bulk upload).
- No scheduled/automatic backups — every run in this release is Administrator-triggered.
- `LargeDatasetSeed.sql`'s row count is a literal argument to `sp_generate_large_dataset`,
  not a configuration setting — edit the script to change it.
