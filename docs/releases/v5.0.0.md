# Smart Customer Ledger — v5.0.0

> *Codename: Replica*

---

## 📖 Overview

Replica is the fifth release milestone of **Smart Customer Ledger**, introducing primary/replica database read-write separation, replica connection health monitoring, and read-heavy reporting offloading.

Replica enhances system read throughput by directing reporting queries to secondary database replicas while maintaining primary database write integrity.

---

## 🎯 Objectives

* Implement separate `ReplicaDbContext` with connection pooling.
* Build `ReplicaHealthService` to verify replica connection status with fast timeout fallback.
* Build `ReplicaAwareReportingService` offloading reporting queries to healthy replicas.

---

## ✨ Added

### 🔄 Replication Architecture

* `ReplicaDbContext.cs` — dedicated DbContext pointing to read replica.
* `ReplicaHealthService.cs` — active connection health checker.
* `ReplicaAwareReportingService.cs` — transparent query routing with primary fallback.

---

## 🏛️ Architecture Decisions

**Failover Transparency.** If the replica database is unreachable, reporting queries automatically fall back to the primary database without user disruption.

---

## ⚠️ Known Limitations

* Multi-database sharding introduced in v6.0.0 Shard.

Replica scales system performance for high-concurrency reporting workloads.
